Written by the Taiga MCP itself, never by an agent, for the User Story transition In Progress -> GPT Validation when the last open child Task reaches Done or Cancelled (PO decision, Issue #335). It records only mechanical facts: the triggering Task and the status of every child Task. It does not claim acceptance criteria, commits, tests or any human validation: GPT still judges the Story cumulatively and Story Done always needs an explicit GPT/PO Story Validation Approval, which cites this comment as its readiness predecessor (exactly as it would cite a Story Validation Handoff). A Cancelled child means terminal readiness only, never accepted scope.

Header metadata: the MCP writes the common header of every governed artifact (status movement, Schema, Author = the authenticated actor whose Task transition triggered the promotion, Model and Effort). The promotion is generated by the MCP and is not callable.

## Fields
- `triggering_task` (text, label=**Triggering Task**): Ref of the child Task whose Done or Cancelled transition made every child terminal.
- `child_tasks` (records, keys=ref|status, label=**Child Tasks**): Every child Task of the Story with its terminal status (Done or Cancelled).
- `promotion_reason` (text, label=**Promotion reason**): Mechanical reason for the promotion.
